Visitors

In some graph algorithms, execution can be divided into meaningful events at which additional behavior may be useful to inject. Such customizability is brought in this library by visitors.

Overview

Visitors are objects intended to be passed as parameters in graph algorithms to customize their execution. They can be used in many ways, from simple observation or recording of information to alteration of the algorithms' execution.

Visitor types do not need to inherit from a specific base type. Instead, they only may implement some specific member functions that algorithms will detect and invoke in accordance to their events.

Events

Events represents meaningful points in the execution of a graph algorithm, such as discovering a vertex or examining an edge during traversal.

Graph algorithms that do accept visitors each describe a specific list of events whose names, order and semantics depend solely on the algorithm itself. More specifically, events with the same name can have different semantics.

Events can be exploited by visitors by implementing the according member functions.

struct some_visitor
{
  void discover_vertex(some_graph const &g, some_vertex v)
  { /* ... do anything ... */ }
  
  void examine_edge(some_graph const &g, some_edge e)
  { /* ... do anything ... */ }
}

Execution control

While events allow injection of behavior amidst a graph algorithm's execution, they can also alter it using specific return values, of the enum class type heim::graphs::visit.

struct some_visitor
{
  heim::graphs::visit examine_edge(some_graph const &g, some_edge e)
  {
    if (should_stop_at_edge(g, e))
      return heim::graphs::visit::stop;
    else
      return heim::graphs::visit::proceed;
  }
}

Each event may not accept all existing values depending on its meaning, but at most accept four:

Name Description
proceed Available with each event, and allows the algorithm to continue its normal execution
stop Available with each event, and stops the algorithm using return, leaving its internal state as is
skip Used with some events to avoid treating the current element but continuing the execution
prune Used with some events to skip elements in continuation of the current element but not itself nor others

Note that using void as an event's return type is equivalent to returning proceed from the event.
Also, the precise consequences of skip and prune in each specific event that accepts these values can still differ depending on the algorithm itself.
