Heim: Graphs

This library provides a common interface to represent and interact with graphs. Inspired directly from the Boost Graph Library (BGL), it focuses on genericity, performance and ease of use, bringing an ideal tool to experts and beginners alike.

Overview

Introduction

In mathematics, graphs are well defined as a pair of two sets: one of its vertices (i.e. nodes, points) and the other of its edges (i.e. arcs, links). In computer science however, many, many different implementations of graphs exist and are used in as many different situations.
Nonetheless, these situations generally demand the same fundamental operations and algorithms from involved graph data structures, independently of how they are implemented. Consequently, to avoid strong coupling to particular implementations and unnecessary code duplication, this library provides a complete generic abstraction for these operations and algorithms.

Graph interface

In order to interact seamlessly with any graph data structure, Heim establishes an interface grounded in theory, to which graph representations can conform independently of their underlying implementation.

At the core of the interface, a small set of customizable traits helps determine the essential characteristics of graph types.
From these traits are established the common primitives through which graphs can be interacted with. These primitives are offered as customization point objects, allowing types such as a std::vector<std::vector<int>> and any other graph representation to provide their own implementations of them.

Since different graph representations provide different capabilities, graph types are not required to support every primitive. They are expected however to support all traits, as these traits are fundamental to their interpretation by the primitives.

Implementations

While the interface is designed to be used with arbitrary graph types, Heim also provides implementations of its own for the most common situations, each one having their own advantages and shortcomings.

adjacency_list is a general-purpose mutable graph type, suited for representing sparse graphs and for being used in many algorithms.
Additional graph representations are planned to cover different use cases and performance tradeoffs, notably adjacency matrix and compressed sparse row representations.

Graph algorithms

Because using graphs often means using their related algorithms, this library offers many of them, built explicitly on its established interface to ensure maximum reusability. Examples of these algorithms range from traversal and shortest paths algorithms, to topological sorting of graphs or component-related algorithms.

Since algorithms interact with graphs in different ways, each formulates certain requirements regarding which primitives need to be available on graph types. Thus, any type that makes available the right primitives can be used as a graph type in the corresponding algorithms.

Properties

A lot of the algorithms proposed in this library require additional information to be associated with vertices or edges, such as weights and costs on edges, or colors on vertices.

Since no assumptions can be made on where or how properties from those objects can be accessed, algorithms make extensive use of the abstractions provided by the Properties library. More often than not, the needed properties of vertices and edges live outside the graph instance itself, namely in associative or indexed containers.

Visitors

In some algorithms, execution can be divided into meaningful events at which additional behavior may be useful to inject. Such customizability is brought in this library by visitors.

Visitors are objects exposing a different callback for each specific event in a given algorithm. Examples of such events include discovering a vertex or examining an edge in a traversal algorithm, or reacting to the color of a vertex in some color-based algorithms.
They can also help directly impact their algorithm's own execution using specific return values, namely stopping the algorithm when a specific vertex or edge has been encountered, and more.

In comparison

Many graph libraries for C++ exist.
The Boost Graph Library (BGL) remains the historical reference for generic graph programming, providing a rich model suited to many representations and concrete situations, but at the cost of a high upfront complexity, making it difficult to approach for beginner and casual users.
Later, LEMON appeared as a generic and efficient alternative with an emphasis on network optimization, but as of today, the library has been discontinued and does not compile past C++17.
Also recently MELON, while providing an excellent implementation and design, also stepped back on some of the genericity and control that others provide to gain performance and simplicity.
More recently, CXXGraph favors a particularly direct and beginner-friendly object-oriented interface, at the cost of tightly coupling algorithms, properties and graph representations to its own data model.
Lastly, graph-v3, being developed alongside an ongoing proposal for a standard C++ graph library, simplifies how properties are represented, but keeps the upfront complexity that they add to the algorithms' interface making it difficult to approach.

Heim aims to provide an elegant way to avoid the main issues of these libraries. By keeping the original genericity of the BGL whilst bringing its interface into a more modern C++, and by offering algorithms with different levels of complexity without hindering performance, Heim caters to both beginners' and experts' needs.

Getting Started

Installation

An installation guide for Heim as a whole can be found directly on the README or main pages.

Creating graphs

To create a simple undirected graph, use the adjacency_list class, along with the interface's primitives to add vertices and edges to it:

heim::adjacency_list g;

auto v0 = heim::graphs::place_vertex(g);
auto v1 = heim::graphs::place_vertex(g);
auto v2 = heim::graphs::place_vertex(g);

auto [e0, placed] = heim::graphs::place_edge(g, v0, v1);
auto [e1, _     ] = heim::graphs::place_edge(g, v0, v2);
auto [e2, _     ] = heim::graphs::place_edge(g, v1, v2);

placed contains true if the edge has been placed, false otherwise. This is important when the graph is not a multigraph, that is a graph with at most one edge between two given vertices.

Some graph types offer additional functionalities on top of the expected interface, which is only a baseline of what is expected of graph representations. The adjacency_list class, for example, supports edge list initialization, as well as implicit conversion of vertices to unsigned integers.

heim::adjacency_list g{{0, 1}, {0, 2}, {1, 2}};

Accessing graphs

This library's interface offers many ways to inspect graphs along with their vertices and edges.

auto vs     = heim::graphs::vertices(g);     // a range of the given graph's vertices
auto es     = heim::graphs::edges(g);        // a range of the given graph's edges
auto oes    = heim::graphs::out_edges(g, v); // a range of a given vertex's edges going out of it
auto dg     = heim::graphs::degree(g, v);    // the number of edges incident with the given vertex
auto [u, v] = heim::graphs::endpoints(g, e); // the two vertices of a given edge
// ... and many more ...

Using algorithms

Each algorithm in this library aims to expose its results through a specific result object.

auto res = heim::graphs::breadth_first_search(g, src); // special dedicated result object
if (res.reached(dst))
  std::print("{}", res.path_from(dst));

auto topo = heim::graphs::topological_sort(g); // a view of the vertices in topological order

While each algorithm provides a simple interface, many parameters can be specified for utmost control over the algorithm.

Providing graph properties

Some of the library's algorithms may require vertices and edges to have certain properties, such as colors on vertices, or weights on edges. Consequently, such algorithms make use of the Properties library, ensuring that no superficial requirement is made on how and where properties need to be accessed.

using graph_type = heim::adjacency_list<>;
using edge_type  = heim::graphs::edge_t<graph_type>;

int get_weight(edge_type);
auto pm_0 = heim::make_property_map(get_weight);

std::map<edge_type, int> m;
auto pm_1 = heim::make_property_map(m);

auto res_0 = heim::graphs::dijkstra(g, src, pm_0);
auto res_1 = heim::graphs::dijkstra(g, src, pm_1);

Code Example

#include <print>
#include <heim/graph.hpp>

using graph_type  = heim::adjacency_list<>;
using vertex_type = heim::graphs::vertex_t<graph_type>;

int main()
{
  graph_type g{};

  vertex_type v0{heim::graphs::place_vertex(g)};
  vertex_type v1{heim::graphs::place_vertex(g)};
  vertex_type v2{heim::graphs::place_vertex(g)};
  vertex_type v3{heim::graphs::place_vertex(g)};

  auto [e0, placed]{heim::graphs::place_edge(g, v0, v1)};
  auto [e1, _     ]{heim::graphs::place_edge(g, v1, v2)};
  auto [e2, _     ]{heim::graphs::place_edge(g, v0, v2)};
  auto [e3, _     ]{heim::graphs::place_edge(g, v2, v3)};

  auto res{heim::graphs::breadth_first_search(g, v0)};
  if (res.reached(v3))
    std::print("{}", res.path_from(v3));
}

Output

[3, 2, 0]
